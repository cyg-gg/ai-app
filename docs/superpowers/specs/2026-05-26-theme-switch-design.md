# 全局主题切换设计

## 目标

为 `client` 端增加一个全局主题切换能力，支持 4 种模式，并满足以下优先级：

1. 手动固定（浅色 / 深色）
2. 定时切换
3. 跟随系统

要求：

- 主题作用于整个应用及所有子页面 / 路由
- 设置永久保存，刷新页面后不重置
- 手动浅色 / 深色一旦选定，其他规则全部失效，始终保持当前主题
- 定时自动切换按每天两个固定时间点生效
- 跟随系统仅作为无手动、无定时配置时的兜底方案

## 当前项目上下文

- 前端位于 `client`
- 主入口为 `client/src/App.jsx`
- 当前样式为深色硬编码主题，主要分布在 `client/src/App.css`、`client/src/index.css`、`client/src/components/*.css`
- 应用是单页多面板结构，顶部没有现成的全局设置入口，因此需要在界面右上角新增一个全局主题菜单

## 用户交互设计

在应用右上角提供一个全局主题按钮，点击后展开菜单，用户可以：

- 直接切换到浅色
- 直接切换到深色
- 选择跟随系统
- 启用或编辑定时切换
- 解除手动固定，恢复自动

菜单内应明确显示当前模式，避免用户不清楚自己处于哪一层规则。

## 状态模型

建议将主题状态拆分为两部分：

### 1. 模式状态

表示当前主题来源：

- `manual-light`
- `manual-dark`
- `schedule`
- `system`

### 2. 配置状态

表示定时配置：

- 亮色时间，例如 `08:00`
- 深色时间，例如 `20:00`
- 定时是否启用

### 3. 实际生效主题

最终只会落到：

- `light`
- `dark`

实际主题由模式状态 + 当前时间 + 系统偏好共同计算。

## 规则与优先级

### 手动固定

当用户显式选择浅色或深色时：

- 写入模式状态为 `manual-light` 或 `manual-dark`
- 立即应用对应主题
- 定时、系统跟随都不再参与计算
- 刷新页面后仍保持该主题

### 定时切换

当模式为 `schedule` 且定时启用时：

- 每天在设定的亮色时间切到浅色
- 每天在设定的深色时间切到深色
- 页面初始加载时按当前时间立即计算应该使用的主题
- 运行过程中在时间点附近自动重新计算并切换

### 跟随系统

当没有手动固定、且没有启用定时方案时：

- 使用 `window.matchMedia('(prefers-color-scheme: dark)')`
- 系统主题变化时同步更新
- 作为兜底方案，不覆盖更高优先级的设置

## 持久化

使用 `localStorage` 保存以下内容：

- 当前模式
- 定时是否启用
- 亮色时间
- 深色时间

应用启动时读取这些值，并恢复对应状态。

需要保证：

- 刷新页面不重置
- 浏览器重启后仍保留
- 没有历史配置时使用合理默认值

## 运行时行为

### 初始化

应用启动时执行一次主题初始化：

1. 读取本地保存的模式和配置
2. 如果是手动模式，直接应用对应主题
3. 如果是定时模式，按当前时间计算主题
4. 如果是系统模式或没有配置，跟随系统偏好

### 监听系统变化

仅在 `system` 模式下监听系统主题变化，避免与更高优先级状态冲突。

### 定时检查

在 `schedule` 模式下建立轻量定时器，定期检查当前时间是否跨过切换点。

建议采用分钟级检查，避免复杂的精确到秒调度，保持实现简单且足够稳定。

## 组件拆分建议

### `useTheme`

建议新增一个主题 Hook，负责：

- 读取和写入 `localStorage`
- 计算当前主题
- 提供切换模式、设置时间、恢复自动等方法
- 监听系统主题变化和定时器

### `ThemeMenu`

建议新增一个右上角菜单组件，负责：

- 展示当前主题模式
- 提供四种模式切换入口
- 提供定时配置入口
- 提供“恢复自动”动作

### 全局样式接入

建议通过给 `document.documentElement` 或根容器加主题标记类名 / data 属性，实现全局主题切换，而不是只改某个局部组件。

## 样式策略

当前项目大量颜色是硬编码深色值，因此需要把应用的核心样式改造成基于主题变量的形式。

建议采用：

- 在 `:root` 定义主题变量
- 使用 `[data-theme='light']` 与 `[data-theme='dark']` 覆盖变量
- 组件样式只引用变量，不直接写死主题色

这样可以最小化后续主题扩展成本。

## 错误与边界情况

### 非法时间值

如果用户输入非法时间：

- 回退到默认值
- 避免主题逻辑中断

### 本地存储不可用

如果 `localStorage` 访问失败：

- 主题仍然可以正常切换
- 仅牺牲持久化能力

### 系统偏好不可用

如果浏览器不支持 `matchMedia`：

- 回退到浅色主题作为安全默认值

## 验收标准

- 用户可在右上角切换主题模式
- 手动浅色 / 深色优先级最高，且刷新后不丢失
- 定时切换可按每天两个固定时间点自动生效
- 跟随系统仅在无更高优先级设置时生效
- 主题对整个应用和所有子页面一致生效
- 页面刷新后主题状态保持不变

## 需要实现时的注意点

- 由于当前样式以深色硬编码为主，先搭好主题变量层，再逐步替换样式
- 主题 Hook 应是单一真相来源，避免多个组件各自维护主题状态
- 定时逻辑要避免重复注册多个监听器或定时器
